## 1. Request flow diagram

```text
OfficerAssistant (src/pages/Assistant.jsx:66-105)
  -> ask(text)
  -> assistantRepo.ask(normalizedText)
  -> api.askAssistant (src/lib/api.js:123)
  -> POST /assistant/query with {"query": "..."}
  -> query_assistant (backend/app/routers/assistant.py:17-44)
  -> run_assistant_query (backend/app/services/assistant_service.py:383-496)
  -> _resolve_query_records (backend/app/services/assistant_service.py:96-381)

  -> AssistantQueryResponse
  -> setAnswer(response)

```

The non-officer path follows the same repository/API/service path, then renders
its answer article at [Assistant.jsx](../src/pages/Assistant.jsx:470).

## 3. What is NOT a cause

- **The browser chip is not a special-case handler.** The three graph/Excel
  chips are entries in the shared `assistantPrompts` array at
  [Assistant.jsx](../src/pages/Assistant.jsx:10-17). Every click calls `ask`
  or `handleSampleClick`, which sends the prompt to the same API.
- **The query is not answered from a frontend static array.** Row data is
  generated by SQLAlchemy queries in `_resolve_query_records`; the chips only
  supply text.
- **The user scope is not absent from the data model.** `User.region_scope`
  and `Institution.region/state` exist at
  [models/__init__.py](../backend/app/models/__init__.py:37-68), and the South
  seed user is configured at [seed_data.py](../backend/app/seed_data.py:201-210).
- **The requested words are not completely ignored in the current source.**
  `graph`, `chart`, `Excel`, and `sheet` are parsed by `parse_presentation` at
  [assistant_service.py](../backend/app/services/assistant_service.py:23-35).
- **The export endpoint is not missing.** The route is implemented at
  [assistant.py](../backend/app/routers/assistant.py:46-123), and the frontend
  calls it through [api.js](../src/lib/api.js:122-124).

## 5. Missing pieces

1. A single display-label boundary for intent IDs; the current label map is
   not applied to `intent_matched` before the API response or UI badge.
2. A real chart component that supports grouped bars, donut charts, and line
   charts rather than a single CSS width bar.
3. A complete planner contract for data intent, filters, ranking, and
   presentation. Current routing is ordered regex/substring matching.
4. Query details such as ranking rule, requested top N, row count, and
   data-as-of in the visible answer for every intent.
5. Server-generated export formatting required by the task: native Charts
   sheet, full formula-injection protection, Indian currency/date formatting,
   status formatting, and exact result-specific filenames.
6. A current end-to-end browser/API test proving the logged-in South user
   receives only the intended mismatch rows.
7. The requested task documents
   `docs/TASK_ASSISTANT_GEMINI.md` and `docs/TASK_ASSISTANT_FIX.md` are absent
   from this checkout, so their requirements cannot be independently
   cross-checked here.

## 6. Recommended minimal fix plan

1. **Normalize response labels at the service/schema boundary.**
   Apply `display_label` to `intent_matched` and all remaining user-visible
   enum fields; add API assertions. Touch `backend/app/services/assistant_service.py`,
   `backend/app/assistant/labels.py`, and assistant tests. Risk: low.
2. **Make the structured response the sole rendered answer.**
   Hide or remove the legacy `rows` list when a structured table exists, and
   render the interpretation, row count, scope, and data-as-of consistently.
   Touch `src/pages/Assistant.jsx` and its stylesheet. Risk: medium.
3. **Replace the CSS bar placeholder with a typed chart renderer.**
   Support the backend chart metadata and empty/single-row states. Touch
   `src/pages/Assistant.jsx` and `src/styles/officer-assistant.css`. Risk: medium.
4. **Expand the parser into independent intent, filter, ranking, and
   presentation tokens.** Preserve the narrow mismatch-before-unmatched rule,
   then add multilingual synonyms and follow-up context. Touch
   `backend/app/services/assistant_service.py`, schemas, and evaluation tests.
   Risk: medium/high.
5. **Complete export from the immutable snapshot.** Add workbook charts,
   formatting, masking, formula sanitization, and parity tests. Touch
   `backend/app/routers/assistant.py` and export tests. Risk: medium.
6. **Restart the backend before manual reproduction.** The in-memory cache is
   ten minutes and can preserve an earlier result in a running process.
   Risk: operational only.

## 8. Open questions for the project owner

1. Should the API stop returning internal enums entirely, or should the UI use
   `display_label`-style data from a response `intent_label` field?
2. Is Basic mode intentionally the only deployed mode, or should the Gemini
   planner be enabled after its schema and privacy contract are completed?
3. Should a graph request automatically download a requested Excel file, or
   only make the button available?
4. Which charting library, if any, is approved for the existing frontend?
5. Should the historical four-row observation be validated against a fresh
   backend restart and a newly seeded database before implementation begins?
